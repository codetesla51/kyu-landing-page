Three engines. One queue.

On Start(), Kyu launches three concurrent goroutines. They run independently, coordinated only through PostgreSQL and Redis. No internal message bus. No shared state.

01 · goroutine
Worker Pool

Pops job IDs from Redis sorted set. Fetches full record from Postgres. Runs your registered handler. Writes status back. Failed jobs with retries are re-queued with exponential backoff.

02 · goroutine
Scheduler

Ticks every 5 seconds. Queries Postgres for scheduled or failed jobs whose time has arrived. Pushes their IDs back into Redis. Postgres is the clock, Redis is the fast lane.

03 · goroutine
Stale Reaper

Ticks every 60 seconds. Finds any job stuck in running state past its StaleJobTimeout. Resets it to pending. Handles crashed workers without manual intervention.

Every job. Full history.

Every state transition is written to PostgreSQL. There is no ephemeral in-memory state. You can query job history with plain SQL at any time.

dp
Durable by default

PostgreSQL holds every job record. Jobs survive a Redis restart. Nothing is lost.

eb
Exponential backoff

Failed jobs retry with 1s, 2s, 4s delay. Never hammer a downstream service on failure.

pq
Priority queues

Higher priority score = processed first. Control ordering per job at enqueue time.

sj
Scheduled jobs

Pass a ScheduledAt pointer to run at a future time. nil means run now.

sr
Stale job reaper

Detects and resets jobs from crashed workers automatically. No manual cleanup.

mw
Middleware system

Wrap every job with logging, timing, panic recovery. Composable and ordered.

pg
Prometheus + Grafana

Full metrics out of the box. Pre-built Grafana dashboard included. Per-instance registry, no conflicts.

ro
RunOnce / Cron mode

Drain the queue and exit. Pair with cron or a Kubernetes CronJob for scheduled batch processing.

How Kyu fits the landscape.

Redis-only queues like Asynq are fast but fragile — if Redis loses data, your jobs are gone. Postgres-only queues like River are durable but don't get Redis's O(log N) sorted set for priority scheduling. Kyu uses both. Postgres is the ledger. Redis is the dispatcher.
